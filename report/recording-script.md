**하지 말 것**: 수식 설명. 관객은 알고리즘을 알 필요가 없다.

## 클립 3 — 성공했다는데 안 된다 ★ (2분)

같은 스크립트가 이어서 2·3단계를 출력한다.

```
2단계 — 그 결과를 컴파일하면?
  ✗ softmax    error: 'cooperative_groups/reduce.h' file not found
  ✗ attention  error: 'hipblas.h' file not found
  ✗ flash      error: no matching function for call to 'rsqrtf'
  변환은 "성공"했지만 빌드는 안 된다

3단계 — LLM 이 수정한 뒤
  ✓ softmax    통과
  ✓ attention  통과
  ✓ flash      통과
```

**말할 것**
1. 변환기는 성공했다고 했는데 컴파일이 안 된다
2. 화면에 3건이지만 **실제로는 5회차에 걸쳐 11건**이었다
   (첫 에러가 컴파일을 중단시켜 파일당 하나씩만 보인다 — 화면 하단에 그렇게 적혀 있다)
3. **이 11건은 전부 컴파일러가 알려준다** → LLM 이 자동으로 고칠 수 있다
4. **그런데 컴파일이 통과한 게 끝이 아니었다** ← 클립 4로 넘어가는 문장

**절대 하지 말 것**: 화면의 3건을 11건처럼 말하기. 화면과 말이 어긋나면 신뢰를 잃는다.

## 클립 4 — 조용히 틀리는 구간 ★★ 핵심 (2분, 슬라이드)

터미널이 아니라 **코드**를 띄운다. **이 클립이 제품 설명이다.**

### 4-1. 컴파일 통과 후에 8건이 더 나왔다

```
Phase 2 (컴파일)     11건  ← 컴파일러가 알려줌
Phase 3 (MI300X 실행) 8건  ← 실제로 돌려봐야 나옴
                     ────
                      19건
```

**말할 것**: "컴파일이 됐다는 건 맞다는 뜻이 아닙니다."

### 4-2. 호스트 `max` — 가장 강력한 사례

```c
max_el = max(max_el, out[i]);      // CUDA 에서는 정상인 코드
```

**말할 것**
- HIP 에서는 이 `max` 가 **정수 버전으로 해석된다**
- 소수가 정수로 잘리고 결과가 **905987520** 같은 쓰레기값이 된다
- 컴파일 통과. 크래시 없음. **경고 한 줄만 나온다**
- **원본에 우연히 들어 있던 검사문 하나가 유일한 방어선이었다**
- "그게 없었으면 아무도 몰랐습니다"

### 4-3. 글자까지 같은 두 줄

```c
void softmax_forward_online2(...) {                      // 커널 6
    const int grid_size = ceil_div(N * 32, block_size);  // ✅ 옳다
}

void softmax_forward_online8(...) {                      // 커널 8
    const int grid_size = ceil_div(N * 32, block_size);  // ❌ 64 여야 한다
}
```

**말할 것**
- NVIDIA 는 한 조가 32명, AMD 는 64명이다
- **같은 파일, 글자까지 똑같은 두 줄인데 한쪽만 틀리다**
- 커널 6은 32명 조를 명시했고, 커널 8은 하드웨어에 물어본다 — 그 차이다
- **찾아서 바꾸기로 처리하면 맞는 쪽을 망가뜨린다**
- 코드가 뭘 하는지 읽어야만 알 수 있다

### 4-4. 결론 슬라이드

| 신호 | 건수 | LLM 루프가 도는가 |
|---|---|---|
| 컴파일러가 알려준다 | 15 | ✅ |
| 런타임 에러 코드 | 1 | ✅ |
| **아무도 알려주지 않는다** | **3** | ❌ |

**말할 것**
- **19건 전부 LLM 이 고쳤습니다.** 사람이 손으로 고친 건 없습니다
- 어려워서 멈추는 게 아닙니다. **틀렸다고 알려주는 게 없어서** 멈춥니다
- 컴파일 에러는 "다시 해봐"라고 말할 근거를 줍니다. **답만 틀리는 버그는 안 줍니다**
- **그래서 제품은 고치는 것부터가 아니라, 틀렸다고 알려주는 것부터입니다**

## 클립 7 — 숫자 세 개 (30초, 슬라이드)

```
   무료 도구가 해준 것       164 줄
   그 뒤에 남은 것            19 건
   아무도 안 알려준 것          3 건
```

**말할 것**
- 표본은 2,294줄 3파일이다. **이 비율을 업계 전체로 확대하지 않는다**
- 중요한 건 숫자가 아니라 **그 3건의 성격**이다
- 셋 다 "컴파일도 되고 크래시도 안 나면서 답만 틀리는" 부류다
- **정답 대조 장치가 없으면 발견조차 못 한다** ← 제품의 자리

### 여기에 한 장 더 붙인다 — 반복 매출 근거

```
   ROCm 6.3 → 7.0.2 로 올렸을 때 다시 깨진 것    4 건
```

- 없던 API 를 채웠더니 **중복**이 됐고, 있던 API 는 **사라졌다**
- **"NVIDIA → AMD 한 번으로 끝나는 일이 아닙니다. 올릴 때마다 다시 깨집니다"**
- 한 번 팔고 끝나는 변환 서비스가 아니라 **계속 돌아야 하는 검증 파이프라인**이다
