# 데모 설계 — 비엔지니어에게 "동작한다"를 각인시키기

대상: 이 작업을 요청한 사람 · 투자자. **엔지니어가 아니다.**

## 전제

엔지니어는 `PASS` 를 보고 납득한다. 비엔지니어는 **"같다"를 눈으로 봐야** 납득한다.

지금 산출물은 이렇게 생겼다:
```
[RESULT] status=PASS max_rel_err=1.815e-06 time_ms=2.7174
```
이건 아무것도 각인시키지 못한다. `Hello World` 나 "키보드를 누르니 캐릭터가 움직인다"가
강력한 이유는 **판단이 필요 없기 때문**이다. 보면 안다.

> **규칙: 모든 증거를 (a) 눈에 띄게 같은 그림 · (b) 빨강→초록 · (c) 숫자 하나
> — 이 셋 중 하나로 바꾼다.**

## 장치 1. "차이 이미지가 새까맣다" — 실측 완료

어텐션 출력은 행렬이다. 행렬은 그림으로 그릴 수 있다.

세 장을 나란히 띄운다.

| NVIDIA GTX 970 | AMD MI300X | **차이** |
|---|---|---|
| 열지도 | 열지도 | **완전한 검정** |

```
최대 절대오차 : 2.980e-08
최대 상대오차 : 3.783e-07
```
→ `report/demo-images/real/compare.png`

검정 = 0 = 다른 데가 없음. 설명이 필요 없다.
입력은 결정적 난수(xorshift32)로 두 플랫폼에서 **비트 단위 동일**하게 고정했다.

### ★ 반드시 대조군을 먼저 보여준다

한 장만 보여주면 "검정이 원래 검정인지" 관객이 알 수 없다.
**일부러 틀린 버전을 먼저** 띄우면 차이 패널에 불이 들어온다.
→ `report/demo-images/broken/compare.png`

그러면 검정 화면이 "통과"를 뜻한다는 것을 관객이 **스스로** 안다.

### 구현 (완료)
- `41_dump_reference.sh` 가 출력 행렬을 raw float32 로 저장
- `40_demo_images.py` 가 열지도 3장 생성 (표준 라이브러리만 사용)
- 차이 패널은 **데이터 범위가 아니라 허용오차로 정규화**한다.
  데이터 범위로 정규화하면 명백한 오류도 검정으로 보여서 데모가 죽는다 (실제로 겪었다)
- `BREAK=1` 은 online softmax 의 재조정 계수를 제거한 **진짜로 잘못된 커널**을 만든다.
  조작된 데이터가 아니다 — 그래서 보고서 신뢰도 자체를 올린다

## 장치 2. 빨강 → 초록 ★ 핵심

여기서 대부분이 실수한다. **다 잘 돌아가는 것만 보여주면 관객은 뭐가 어려웠는지 모른다.
그러면 이 회사 제품이 왜 필요한지도 모른다.**

우리에겐 완벽한 재료가 있다. **실제로 겪은 19건**이다.

### 시연 순서 (30초)
1. 무료 변환 도구(hipify)를 돌린다 → **"성공"** 이라고 나옴 (164줄 치환)
2. 컴파일한다 → **실패.** 에러가 쏟아진다
3. LLM 이 고친다 → **컴파일 통과**
4. MI300X 에서 실행한다 → **돌아감. 크래시 없음**
5. 정답과 비교 → **빨간 FAIL**, 차이 이미지에 불이 들어옴
6. 다시 고친다 → **초록 PASS**, 차이 이미지 새까맣게

**5번이 이 데모의 전부다.** 4번에서 멈추는 도구는 세상에 많다.

### ★ 이야기의 핵심은 "어려움"이 아니라 "신호의 유무"다

**19건 전부 LLM 이 고쳤다.** 사람이 손으로 고쳐야 하는 건 하나도 없었다.
그러니 "우리는 뛰어난 전문가가 있다"는 이야기가 아니다.

자동화가 멈추는 지점은 **어려운 곳이 아니라 아무도 틀렸다고 알려주지 않는 곳**이다.

| 신호 | 건수 | LLM 루프가 도는가 |
|---|---|---|
| 컴파일러가 알려준다 | 15 | ✅ 고치고 재컴파일 → 즉시 판정 |
| 런타임 에러 코드 | 1 | ✅ 판정 가능 |
| **아무도 알려주지 않는다** | **3** | ❌ **여기서 루프가 시작조차 못 한다** |

컴파일 에러는 LLM 에게 "다시 해봐"라고 말할 근거를 준다.
**답만 틀리는 버그는 그 근거를 주지 않는다** — 재컴파일해도 화면이 똑같다.

> **그래서 제품은 "고치는 것"이 아니라 "틀렸다고 알려주는 것"부터다.**

### 무대에 올릴 실제 사례 — 호스트 `max`

```c
max_el = max(max_el, out[i]);      // 호스트 코드. CUDA 에서는 정상
```

HIP 호스트에는 `int max(int,int)` 만 보인다. float 가 int 로 변환되고
`-inf` 는 UB 라 **905987520 같은 쓰레기값**이 나온다.

| | |
|---|---|
| 컴파일 | 통과 (경고 한 줄) |
| 실행 | 크래시 없음 |
| 결과 | 쓰레기값 |
| 발견 | **원본에 우연히 있던 `assert` 가 유일한 방어선** |

"우연히 있던 assert 가 유일한 방어선이었다"는 문장이 이 데모에서 가장 강력하다.
**그 assert 가 없었으면 아무도 몰랐다.**

### 무대에 올릴 두 번째 사례 — 글자까지 같은 두 줄

```c
void softmax_forward_online2(...) {                      // 커널 6
    const int grid_size = ceil_div(N * 32, block_size);  // ✅ 옳다
}   // 커널 안: cg::tiled_partition<32>

void softmax_forward_online8(...) {                      // 커널 8
    const int grid_size = ceil_div(N * 32, block_size);  // ❌ 64 여야 한다
}   // 커널 안: blockDim.x / warpSize
```

**같은 파일, 글자까지 동일한 두 줄인데 한쪽은 맞고 한쪽은 틀리다.**
NVIDIA 는 한 조가 32명, AMD 는 64명이다. 어느 쪽이 틀렸는지는
**각 커널이 스레드를 어떻게 배치하는지 읽어야만** 알 수 있다.

`sed` 로 일괄 치환하면 **맞는 쪽을 망가뜨린다.** 이게 "찾아서 바꾸기"로 안 되는 이유다.

## 장치 3. 숫자 세 개

슬라이드 한 장에 이것만. (전부 실측)

```
   무료 도구가 해준 것       164 줄
   그 뒤에 남은 것            19 건
   아무도 안 알려준 것          3 건    ← 여기가 제품의 자리
```

### 이 숫자를 어떻게 읽는가
| 숫자 | 사업적 의미 |
|---|---|
| 자동 164줄 | 공짜 도구가 이미 한다 → **여기엔 사업이 없다** |
| 신호 있는 16건 | LLM 루프가 자동으로 수렴 → **제품의 기능** |
| **신호 없는 3건** | 정답 대조 장치가 없으면 발견 불가 → **제품의 존재 이유** |

### 붙여서 말할 한 문장

> "무료 도구가 164줄을 해줍니다. 그다음 19건이 남는데, 16건은 컴파일러가 알려주니
>  LLM 이 알아서 수렴시킵니다. **문제는 나머지 3건입니다** — 컴파일도 되고
>  크래시도 안 나면서 답만 틀립니다. 저희 제품은 고객이 이미 갖고 있는
>  NVIDIA 결과물을 정답으로 넣어서, 그 3건을 **자동으로 잡아냅니다.**"

### ⚠ 이 숫자로 하지 말아야 할 것

**표본은 2,294줄짜리 파일 3개뿐이다.** 여기서 나온 비율을 산업 전체로 외삽해
시장 규모를 말하면, 이 프로젝트가 지키려는 "실측값 없는 숫자는 쓰지 않는다"를
스스로 어기는 것이다.

정직한 표현:
> "2,294줄 표본에서 신호가 없던 건 3건이었고,
>  **그 3건이 어떤 성격인지**가 여기 있습니다."

숫자보다 **3건의 성격**이 설득력이다.

## 장치 3-B (보너스). "한 번 고치면 끝이 아니다"

이건 계획에 없었는데 실측에서 나왔다. **반복 매출 근거가 된다.**

ROCm **6.3 에서 통과한 코드가 7.0.2 에서 4건 깨졌다.**

| 방향 | 무슨 일 |
|---|---|
| 없던 게 생김 | 6.3 에 `__syncwarp` 가 없어 우리가 채웠는데, 7.x 가 제공해서 **중복 정의** |
| 있던 게 사라짐 | `hipblasGemmStridedBatchedEx_v2` 가 7.x 에서 **제거** |

> **"NVIDIA → AMD" 한 번으로 끝나는 일이 아닙니다.
>  ROCm 을 올릴 때마다 다시 깨집니다."**

한 번 팔고 끝나는 변환 서비스가 아니라 **계속 돌아야 하는 검증 파이프라인**이라는 뜻이다.

## 하지 말아야 할 것

- **성능 숫자를 쓰지 않는다.** 기준선이 GTX 970(2014, 3.5 TFLOPS)이고
  MI300X 는 163 TFLOPS 다. 그 격차는 이식 품질이 아니라 하드웨어 세대 차이다.
  동급 NVIDIA 재측정은 **비용 대비 얻는 것이 없어 접었다.** 성능은 이 데모의 주제가 아니다.
  → 970 기준선은 **정확도 검증용**으로만 쓴다
- 실측값 없는 칸을 추정치로 채우지 않는다
- "거의 자동으로 됩니다" 같은 표현을 쓰지 않는다. 숫자 세 개로 말한다
- **"우리는 뛰어난 전문가가 있습니다"로 말하지 않는다.** 19건 전부 LLM 이 고쳤다.
  파는 것은 전문성이 아니라 **루프와 그 루프의 종료 조건**이다
- 3/19 같은 비율을 산업 전체로 외삽하지 않는다
