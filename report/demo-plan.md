# 데모 설계 — 비엔지니어에게 "동작한다"를 각인시키기

대상: 이 작업을 요청한 사람 · 투자자. **엔지니어가 아니다.**

## 전제

엔지니어는 `PASS` 를 보고 납득한다. 비엔지니어는 **"같다"를 눈으로 봐야** 납득한다.

지금 산출물은 이렇게 생겼다:
```
[RESULT] status=PASS max_rel_err=3.2e-07 time_ms=1.4832
```
이건 아무것도 각인시키지 못한다. `Hello World` 나 "키보드를 누르니 캐릭터가 움직인다"가
강력한 이유는 **판단이 필요 없기 때문**이다. 보면 안다.

> **규칙: 모든 증거를 (a) 눈에 띄게 같은 그림 · (b) 빨강→초록 · (c) 숫자 하나
> — 이 셋 중 하나로 바꾼다.**

---

## 장치 1. "차이 이미지가 새까맣다"

어텐션 출력은 행렬이다. 행렬은 그림으로 그릴 수 있다.

세 장을 나란히 띄운다.

| NVIDIA 결과 | AMD(MI300X) 결과 | **차이** |
|---|---|---|
| 열지도 | 열지도 | **완전한 검정** |

검정 = 0 = 다른 데가 없음. 설명이 필요 없다.
**일부러 틀린 버전을 먼저 보여주면 세 번째 이미지에 불이 들어온다.**

### 구현
- 하네스에 `--dump <파일>` 옵션 추가 → 출력 행렬을 PGM/PNG 로 저장
- 세 번째 이미지는 `|A − B|` 를 같은 스케일로 정규화해 저장
- 이미지가 완전한 검정이면 최대 오차값도 함께 자막으로 (`max diff = 3.2e-07`)

---

## 장치 2. 빨강 → 초록 ★ 핵심

여기서 대부분이 실수한다. **다 잘 돌아가는 것만 보여주면 관객은 뭐가 어려웠는지 모른다.
그러면 이 회사 제품이 왜 필요한지도 모른다.**

우리에겐 완벽한 재료가 있다. 실제로 겪은 문제다.

> `#define WARP_SIZE 32` — NVIDIA 는 32명이 한 조, AMD 는 64명이 한 조다.
> 그대로 옮기면 **컴파일도 되고, 크래시도 안 나고, 답만 틀린다.**

### 시연 순서 (30초)
1. 자동 변환기를 돌린다 → **"성공"** 이라고 나옴
2. 실행한다 → **돌아감.** 에러 없음
3. 정답과 비교 → **빨간 FAIL**, 차이 이미지에 불이 들어옴
4. 사람이 판단해서 고친다
5. 다시 실행 → **초록 PASS**, 차이 이미지 새까맣게

이 5단계가 제품의 존재 이유를 30초에 설명한다.
**"자동 변환이 성공했다고 말하는데도 답이 틀리는 구간"** — 그게 팔 물건이다.

### 구현
- `WARP_SIZE` 오류를 **일부러 살려둔 바이너리**를 따로 빌드해 둔다
- 이건 시연용 장식이 아니라 **"이 버그가 실재한다"를 실측으로 증명**하는 것이라
  보고서 신뢰도 자체를 올린다

## 장치 3. 숫자 세 개

슬라이드 한 장에 이것만. (Phase 2 실측값 — 이미 확보됨)

```
   자동으로 된 것       164 줄
   도구가 놓친 것        11 건
   사람이 판단한 것       3 건    ← 여기가 제품의 자리
```

투자자는 이 세 숫자에서 시장 크기를 계산한다.

---

## 장치 4 (다음 단계). 같은 질문 → 같은 대답

가장 강력한 데모.

> 화면 둘. 왼쪽 NVIDIA, 오른쪽 AMD.
> 같은 문장을 넣으면 **글자 하나까지 똑같은 답**이 나온다.

설명이 아예 필요 없다. 다만 커널 3개가 아니라 **모델 전체**를 옮겨야 한다
(= 보고서의 "다음 단계: 앱 전체 변환, 2주 / ~$150").

**이번 데모의 마지막 슬라이드로 쓴다** — "이게 되면 이렇게 됩니다".

## 진행 상황을 투자자 언어로 번역

| 실제로 한 일 | 하는 말 |
|---|---|
| Phase 0 — 범위 확정, 하네스 작성 | "무엇을 측정할지 먼저 못 박았습니다" |
| Phase 2 — hipify + 컴파일 이슈 11건 수정 | **"NVIDIA 전용 코드가 AMD 에서 빌드됩니다"** |
| GPU 없이 컴파일되도록 분리 | "실험 비용을 $30 → $15 로 줄였습니다" |
| 아직 남은 R1 | "'되는 것처럼 보이는데 틀린' 구간이 실재합니다" |

**현재 위치 한 문장:**
> "AMD 용으로 만들어졌다"까지 끝났고, "AMD 에서 정말 맞게 돈다"를 확인하는 중입니다.

## 하지 말아야 할 것

- **세대가 다른 GPU 의 성능 숫자를 헤드라인에 쓰지 않는다.**
  기준선이 GTX 970(2014, 3.5 TFLOPS)이면 MI300X(163 TFLOPS)와의 격차는
  이식 품질이 아니라 하드웨어 세대 차이다. 그 숫자를 자랑하면 신뢰도가 무너진다.
  → 970 기준선은 **정확도 검증용**으로 쓰고, 성능 비교는 A100/H100 재측정 후에만 발표한다.
- 실측값 없는 칸을 추정치로 채우지 않는다.
- "거의 자동으로 됩니다" 같은 표현을 쓰지 않는다. 숫자 세 개로 말한다.
