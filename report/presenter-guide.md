# 2. 왜 이 일이 돈이 되는가 (배경, 2분)

발표 맨 앞에 이 맥락을 깔아야 나머지가 이해된다.

**AI 계산은 GPU라는 칩에서 돕니다. 이 시장은 NVIDIA가 사실상 독점입니다.**

독점의 이유는 칩 성능이 아니라 **소프트웨어**다.
전 세계 AI 코드가 NVIDIA 전용 언어(**CUDA**)로 쓰여 있다.
AMD가 좋은 칩(**MI300X**)을 만들어도, 코드가 안 돌면 살 이유가 없다.

**그래서 "NVIDIA 코드를 AMD에서 돌게 만드는 일"에 수요가 있습니다.**

AMD도 이걸 안다. 그래서 **무료 변환 도구(hipify)** 를 만들어 뿌린다.

> **여기서 질문: 무료 도구가 있는데 왜 돈을 내겠는가?**
>
> **이 발표는 그 질문 하나에 답하는 것입니다.**

## 구간 4 — 조용히 틀림 ★★ 여기가 제품 설명 (3분)

터미널이 아니라 **슬라이드**다. 천천히 가라.

### 4-1. "컴파일이 됐다는 게 맞다는 뜻이 아닙니다"

```
   컴파일 단계에서 나온 문제      11 건   ← 컴퓨터가 알려줌
   실제로 AMD 칩에서 돌려보니      8 건   ← 돌려봐야 나옴
                               ──────
                                19 건
```

**말할 것**: "프로그램이 만들어졌다고 해서 맞게 도는 건 아니었습니다.
실제 칩에 올려보니 8건이 더 나왔습니다."

### 4-2. 가장 강력한 사례 — 큰 값 고르기

```c
max_el = max(max_el, out[i]);     // NVIDIA에서는 멀쩡한 코드
```

**말할 것 (천천히)**
- "두 숫자 중 **큰 쪽을 고르는** 아주 평범한 한 줄입니다."
- "NVIDIA에서는 소수를 넣으면 소수로 비교합니다."
- "**AMD에서는 이 줄이 정수용으로 해석됩니다.** 0.7이 0이 됩니다."
- "결과가 **905987520** 같은 쓰레기 숫자가 됐습니다."

그리고 이 표를 띄운다:

| | |
|---|---|
| 프로그램이 만들어졌나 | **네** |
| 실행했을 때 멈췄나 | **아니오** |
| 에러 메시지가 났나 | **아니오** (경고 한 줄뿐) |
| 답이 맞았나 | **아니오** |

**★ 마무리 대사 (이 발표에서 가장 강한 문장)**
> **"원본 코드에 우연히 들어 있던 검사문 하나가 유일한 방어선이었습니다.
> 그게 없었으면 아무도 몰랐을 겁니다."**

여기서 한 박자 쉬어라.

### 4-3. 글자까지 똑같은 두 줄

```c
void softmax_forward_online2(...) {                      // 6번 커널
    const int grid_size = ceil_div(N * 32, block_size);  // ✅ 맞다

void softmax_forward_online8(...) {                      // 8번 커널

```

**말할 것**
- "**같은 파일 안에 있는, 글자 하나까지 똑같은 두 줄입니다.**"
- "그런데 위는 맞고 아래는 틀립니다."
- "NVIDIA는 한 조가 32명이고 AMD는 64명입니다. 저 `32`가 그 뜻입니다."
- "위 줄이 속한 함수는 '32명 조'를 따로 지정해 놨고,
  아래 줄이 속한 함수는 **칩에게 직접 물어봅니다.** 그 차이입니다."
- **"찾아서 바꾸기로 처리하면 맞는 쪽을 망가뜨립니다."**
- "코드가 뭘 하는지 **읽어야만** 알 수 있습니다."

### 화면에 나오는 것과 그 뜻

**① 접속 화면**
```
root@rocm-7-14-software-gpu-mi300x1-192gb-devcloud-atl1:~#
```
- 뜻: 클라우드에 빌린 AMD MI300X 서버에 원격 접속한 상태
- 말할 것: "시간당 2달러에 빌린 실제 AMD 칩입니다."

**② 환경 확인**
```
AMD Instinct MI300X VF · gfx942 · ROCm 7.0.2
```
- 뜻: 칩 이름 / 칩 모델 코드 / AMD 소프트웨어 버전
- 말할 것: 넘어가도 된다. 물어보면 "칩 사양 확인 단계"

**③ ★ 이 줄을 반드시 짚어라**
```
Skipping block size 32 for kernel 8 (needs >= wavefront size).
```
- 뜻: **"AMD는 한 조가 64명이라 32명 단위는 건너뛴다"**
- 말할 것: **"방금 슬라이드에서 설명한 32 대 64 문제가, 지금 화면에서 프로그램이
  직접 말하고 있습니다."**
- **구간 4와 구간 5를 잇는 유일한 장면이다.** 놓치지 마라.

**④ 통과 순간**
```
All results match. Starting benchmarks.
```
- 뜻: **"모든 결과가 정답과 일치한다"**
- 말할 것: "정답은 별도로 계산해 두고 하나하나 대조합니다. 전부 일치했습니다."

**⑤ 최종 결과**
```
[RESULT] kernel=flash_attention_fwd status=PASS max_rel_err=1.815e-06
```
- 뜻: `PASS` = 통과 / `max_rel_err` = 정답과의 최대 오차 = **0.0000018**
- 말할 것: "오차가 백만분의 2 수준입니다. 소수점 계산 순서 차이에서 오는
  불가피한 값이고, 틀린 게 아닙니다."

**⑥ ★ 핵심 컷 — 요약 표**
```
=== 실행 시간 ===
  run:softmax_hip:k1    150s   rc=0
  run:softmax_hip:k2     15s   rc=0
  ...
  run:attention_hip:k6    3s   rc=0
  run:flash_hip           1s   rc=0
```
- 뜻: `rc=0` 은 **"오류 없이 끝났다"**
- 말할 것: **"15개 전부 통과입니다."**
- **영상에서 가장 오래 보여줄 장면.** 자막으로 `15/15 PASS` 를 크게 얹어라.

### 편집 시 잘라낼 구간
`softmax k1`(150초), `k5`(143초), `attention k1`(47초), `k2`(132초) 는
일부러 느리게 짠 비교용 버전이라 화면이 멈춘 것처럼 보인다. **잘라내라.**
`rocprof` 출력도 길기만 하고 관객이 읽을 게 없다.

### ⚠ 화면에 `Mismatch` 라는 글자가 보이면

원본 영상 끝부분 요약 블록에 `Mismatch of out at ...` 같은 줄이 몇 개 섞여 있다.

**정확도 문제가 아니다.** 세션 기록 파일이 **이어붙이기 방식**이라
수정하기 **전** 실패 기록이 남아 있었고, 요약이 그 파일까지 긁어서 되살린 것이다.
커널별 기록 16개는 **전부 통과**로 남아 있다.

- **가장 좋은 대응: 편집에서 그 부분을 잘라낸다.** (스크립트는 이미 고쳤다)
- 잘라내지 못했고 누가 지적하면:
  > "기록 파일이 누적식이라 수정 전 이력이 같이 잡힌 것입니다.
  > 커널별 판정은 전부 통과로 남아 있고, 요약 코드는 수정했습니다."

**숨기지 말고 위처럼 설명하라.** 로그를 그대로 공개하는 게 이 프로젝트의 신뢰 근거다.

"원래 검정 아닌가?"라고 생각한다. 불붙은 걸 먼저 봐야 검정이 "통과"로 읽힌다.

**덧붙일 한마디**
> "양쪽에 넣은 입력값은 **완전히 똑같이** 맞춰 두었습니다. 우연이 아닙니다."

**⚠ 정직하게 밝힐 것**: 버그 버전은 조작한 그림이 아니라
**실제로 계산이 틀리도록 코드를 고쳐서 돌린 결과**다. 물어보면 그렇게 답하라.

- "셋 다 프로그램이 멀쩡히 돌면서 답만 틀리는 종류입니다."

```
   AMD 소프트웨어를 6.3 → 7.0.2 로 올렸더니 다시 깨진 것   4 건
```

  AMD 버전을 올릴 때마다 다시 깨집니다."**
- "한 번 팔고 끝나는 변환 서비스가 아니라, **계속 돌아야 하는 검증 장치**라는 뜻입니다."

# 5. 예상 질문과 답 ★ 여기를 제일 많이 읽어라

### Q1. "AMD가 NVIDIA보다 얼마나 빠른가요?"

**가장 많이 나올 질문이고, 답을 잘못하면 신뢰를 잃는다.**

> **"이번 발표에서 성능은 말씀드리지 않습니다.**

> 11년 차이 나는 칩끼리 비교해서 'AMD가 몇 배 빠르다'고 말하면 그건 거짓말입니다.
> **저희가 증명한 것은 속도가 아니라 '답이 맞다'는 것입니다.**"

덧붙일 것:
> "동급 NVIDIA 칩을 빌려 다시 재는 건 가능하지만, 이 제품의 가치와 무관해서
> 비용을 쓰지 않기로 했습니다. 필요하시면 언제든 잴 수 있게 코드는 준비돼 있습니다."

**★ 이 답이 오히려 신뢰를 만든다.** "모르는 건 모른다고 하는 팀"이 된다.

### Q2. "무료 도구가 있는데 왜 돈을 내나요?" ← 발표의 핵심 질문

> "무료 도구는 164줄을 바꿔주고 '성공'이라고 말합니다.
> **그 상태로는 프로그램이 만들어지지도 않습니다.**
> 그 뒤에 19건이 남고, 그중 3건은 **프로그램이 멀쩡히 돌면서 답만 틀립니다.**
> 무료 도구는 그걸 알려주지 않습니다."

### Q3. "AI가 다 고쳤다면서요? 그냥 ChatGPT 쓰면 되는 거 아닌가요?" ← 가장 날카로운 질문

**이 질문을 반드시 대비하라. 여기서 무너지면 발표 전체가 무너진다.**

> "맞습니다. **19건 전부 AI가 고쳤습니다.**
> 그런데 AI는 **'여기가 틀렸다'는 신호가 있어야** 고칩니다.
> 에러 메시지가 곧 '다시 해봐'라는 신호입니다.
>
> **답만 틀리는 3건은 그 신호를 안 줍니다.** 몇 번을 다시 돌려도 화면이 똑같습니다.
> AI 입장에서는 다 고친 것처럼 보입니다.
>
> **저희가 만드는 건 AI가 아니라, AI에게 '아직 틀렸다'고 말해주는 장치입니다.**
> 고객이 이미 NVIDIA에서 뽑고 있는 결과물을 정답으로 넣어서요."

### Q4. "3건이면 별거 아니지 않나요?"

> "그 3건 중 하나는 **결과가 9억이라는 쓰레기 숫자로 나오는** 버그였습니다.
> 발견된 이유는 원본 코드에 **우연히** 검사문이 하나 있었기 때문입니다.
> 그게 없었으면 아무도 몰랐습니다.
>
> **건수가 아니라 '발견될 수 있었는가'가 문제입니다.**
> 답이 조금씩 틀린 채로 몇 달 돌아가는 게 최악입니다."

### Q5. "실제 고객 코드는 이것보다 훨씬 클 텐데요?"

> "맞습니다. **표본이 3파일 2,294줄이라는 건 저희가 먼저 밝히고 있습니다.**
> 여기서 나온 비율(19건, 3건)을 그대로 확대하지 않습니다.
>
> 다만 **문제의 성격은 규모와 무관합니다.**
> 코드가 커지면 '조용히 틀리는 구간'은 **비율이 아니라 절대 수가 늘고,
> 사람이 찾기는 더 어려워집니다.** 자동 검증의 필요는 커지지 크지 줄지 않습니다."

### Q6. "왜 2014년 GPU로 비교했나요?"
