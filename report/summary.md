## 자동화 가능 구간 vs 사람이 필요한 구간

### 자동 (hipify, 164줄)
API 이름 치환, 헤더 경로 대부분, 런타임 타입, 커널 런치 문법.

### LLM 보조로 해결 (7건)
| 이슈 | 성격 |
|---|---|
| `rsqrtf` 가 HIP 에선 `__device__` 전용 | 동등 표현으로 치환 |
| hipify 가 ROCm 5.x 평면 include 경로 생성 | 경로 갱신 |
| `__syncwarp()` 부재 | 대응 API 로 치환 |
| `__stcs` 전무 · `__ldcs` 오버로드 부족 | 얇은 호환 계층 |
| `min(int, unsigned)` 첨자 타입 오류 | 캐스트 |
| 호스트 `isfinite` 오버로드 모호 | 명시적 캐스트 |
| `<cuda_bf16.h>` 미변환 | 헤더 치환 |

### ★ 사람 판단 필요 (3건) — **이 목록이 제품의 자리다**

**1. `cg::reduce` 가 HIP 에 아예 없다**
ROCm 6.3 헤더에 `reduce` 심볼 0건. shuffle 로 재구성해야 하는데
`__shfl` 은 스칼라만 받아 구조체는 word 단위로 쪼개야 하고,
`cg::reduce` 는 all-reduce 라 마지막 브로드캐스트가 필요하다.
**빠뜨리면 컴파일도 되고 크래시도 안 나면서 답만 틀린다.**

**2. `__shfl_*_sync` 8곳의 폭 결정**
hipify 가 **전혀 변환하지 않는다.** CUDA 는 폭 32 암묵 고정, AMD 는 웨이브 64.
**같은 파일 안에서 관례가 갈린다** — `warpReduceMax`(`offset=16`) vs `kernel8`(`offset=warpSize/2`).
일괄 치환하면 반드시 틀린다.

**3. `#if` 안에 숨은 정의**
`__CUDACC_VER_MAJOR__` 가드로 감싼 bf16 `__ldcs`/`__stcs` 가 HIP 에서 통째로 사라진다.
hipify 는 전처리기 조건 내부를 해석하지 않고, 에러는 한참 뒤 사용 지점에서 나타난다.

### 변환 불가 / 재작성 필요
cuDNN Flash Attention (attention 커널 10·11) — ROCm 에 1:1 대응 없음.
`ENABLE_CUDNN` 기본 비활성이라 이번 범위에서는 자동 제외됐다.

## 부수 발견 — llm.c 자체의 결함

이식 작업과 별개로 원본 코드에서 두 가지를 찾았다.

1. **fp32 경로가 컴파일되지 않는다.** `common.h` 의 `#else`(fp32) 분기가
   `CUBLAS_LOWP` / `CUBLAS_LOWP_COMPUTE` 를 정의하지 않는데 `attention_forward` 가 11곳에서 쓴다.
   `ENABLE_BF16` 을 끄는 순간 드러난다. (NVIDIA·AMD 양쪽에서 동일하게 발생)
2. **flash 예제 커널의 divergent `__syncthreads()`** — `if (row >= N) return;` 뒤에 배리어가 있어
   N 이 블록 크기의 배수가 아니면 정의되지 않은 동작이다.

## 방법론 (숫자를 신뢰할 수 있는 이유)

- llm.c 내장 `validate_result`(tol 1e-4) · `benchmark_kernel` 을 그대로 사용. 자체 판정 아님
- flash 커널은 별도 하네스 — CPU 레퍼런스 double 누적, **결정적 난수**로 양 플랫폼 입력을
  비트 단위 동일하게 고정 (libc `rand()` 는 구현마다 달라 쓰지 않았다)
- 수정 전 hipify 원본 출력을 커밋해 두고 이후 diff 를 "사람이 한 일"로 계측
- llm.c 커밋 `f1e2ace6` 고정 · 컴파일 플래그 양쪽 동일

## 한계 (선제적으로 밝힌다)

- **성능 비교는 아직 발표할 수 없다.** 현재 기준선은 GTX 970(2014, 3.5 TFLOPS)이고
  MI300X 는 163 TFLOPS 다. 24~47배 격차는 이식 품질이 아니라 하드웨어 세대 차이다.
  → A100/H100 재측정 후에만 성능 숫자를 쓴다
- 이번 측정은 전 구간 **fp32** 다 (기준선 GPU 가 bf16 미지원). 저정밀 경로는 범위 밖
- 문제 크기를 **B=2** 로 줄였다 (Windows TDR 제약). MI300X 도 동일 조건으로 맞춘다
- 커널 단위 비교이며 학습 전체 파이프라인 성능이 아니다
- MI300X 튜닝은 하지 않았다 — 이식성 측정이 목적이지 최적화가 아니다
